# Cross-border Data Compliance (lanzhi-crossborder) — Factory Manual (English)

> Version v2.0.0 · 2026-10-19 · Lanzhi Security Agent, P0 contract layer

## 1. Feature Description

The cross-border data compliance skill is a **pre-departure compliance gate**. Before any cross-border data transfer or overseas feature launch, it runs a compliance check to ensure data storage and transmission align with the target region's data protection laws.

Core capabilities:
- **Three-layer validation**: target region regulation → data classification → transmission link
- **Versioned regulation library**: each region record carries a regulation version, effective date, and legal basis — every conclusion is traceable to a specific version
- **Data classification engine**: auto-detects ID document / biometric / payment info / credentials (sensitive) → personal data → ordinary business data
- **Cross-border charge / payment / tax check**: payment channel / fund settlement / tax registration
- **Dual-channel interface**: voice + click (submit / release / query / export)
- **Human final review**: AI only validates; release requires human confirmation with a recorded reason
- **Undo protection**: report deletion is reversible
- **Audit ingestion**: 16-column contract events ingested into the operation audit log

## 2. Usage

### CLI (no UI dependency)
```bash
# Three-layer validation
python crossborder_check.py --region <region> --data-class <personal|business|sensitive> \
    --links storage,encryption,charge,payment,tax [--override <reason>]

# Auto-classify (pass transfer text instead of --data-class)
python crossborder_check.py --region <region> --content "<transfer text>" \
    --links storage,encryption,charge,payment,tax

# Subcommands
python crossborder_check.py submit   --region <region> --data-class <class> --links <links>
python crossborder_check.py release  --region <region> --reason "<release reason>"
python crossborder_check.py classify --content "<transfer text>"
python crossborder_check.py charge-check --region <region> --charge payment_channel,settlement,tax_registration
python crossborder_check.py register-region --name <region> --tier <se-asia|english> --version <ver> --effective <date>
python crossborder_check.py query    --result PASS --region <region> --limit 20
python crossborder_check.py export   --format md|json|csv
python crossborder_check.py report
python crossborder_check.py clean --file <file>
python crossborder_check.py undo --list | --restore <id>
python crossborder_check.py --selftest                  # 24 self-test cases
```

### Voice commands
- "Overseas check <region> <data>" → run three-layer validation
- "Release cross-border <region> <reason>" → human release (reason recorded)

### Click entry
Overseas Center → Cross-border Data Compliance → Start check / View records

## 3. Security Boundaries

1. **Unregistered region not released**: a target region outside the two market tiers (or unregistered) → BLOCK (CRIT).
2. **Data classification first**: data must be classified before transfer; **sensitive data never crosses the border** — a hit on ID / biometric / payment / credentials → RISK advisory; not released without compliance assessment + human confirmation.
3. **Link completeness**: storage + transport encryption + cross-border charge / payment / tax; missing any required item → BLOCK (CRIT); missing transport encryption is CRIT.
4. **Human final review**: the AI only validates and does not finalize; release requires human confirmation (human_decision=override + reason recorded).
5. **Key red line**: API keys / payment secrets are filled only by the operator; the AI must not open, read, or scan any key file or cloud key configuration.
6. **No tampering with core data**: does not modify any business database; events are append-only (except undo).
7. **No background jobs**: no unattended background tasks or scheduled auto-deploy.
8. **Zero sensitive values on disk**: classification outputs only category + legal basis; no sensitive value is written to logs or reports.

## 4. Compliance Statement

- This tool validates against the target region's **currently effective** data protection laws, using the regulation versions registered in the rule library; it does not presume "it's probably fine".
- BLOCK = halt the launch / transfer, **no data is deleted**; disposition goes through human final review.
- This tool provides **engineering compliance validation**, not legal advice; consult local counsel for region-specific legal applicability.
- Regulation versions are recomputable: any conclusion is traceable to a specific regulation version and effective date.
- Sensitive data cross-border requires a passed compliance assessment plus human confirmation; by default it never crosses.
- Data classification outputs only category and basis — **no sensitive value is ever written to logs or reports**.
